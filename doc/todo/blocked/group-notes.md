## 目标

在「系统设置 → 计费与支付 → 分组定价 → 定价分组」中为每个分组增加可选的「内部备注」，方便运营人员按用途、线路或维护状态查找分组。采用独立的 `GroupNotes` 配置，不新增数据库表、列、索引或迁移。

备注不是「分组可见性」里的用户可见描述。它只随现有 Root 权限的后台设置接口读写，不进入普通用户分组接口、公开定价接口、倍率计算、可见性判断或自动路由。本期不重构分组存储、不增加独立备注接口，也不承诺高频多人并发编辑。

## 数据和接口

- 主数据库继续使用 `options` 表。`key = 'GroupNotes'` 的一行保存全部备注；`value` 是「分组名 → 纯文本备注」的 JSON 字符串，例如 `{"SUP-STDG-PVACP003":"备用线路","SUP-STDG-PVACP002":"仅供测试"}`。分组名称完全匹配、区分大小写；搜索不区分大小写。
- 未保存过时默认 `{}`，不主动写入数据库。去掉备注首尾空白；空白备注不落盘；清空全部备注时保存 `{}`，避免删除配置行后旧实例仍保留旧值。每条备注限 200 个 Unicode 码点，按纯文本展示，不解释 HTML 或 Markdown。内层 JSON 字符串按 UTF-8 计不超过 2 MiB（提交原文和规范化后均检查），超限不得截断或保存。前后端使用相同口径，后端为最终校验方。
- 读写复用 `GET /api/option/`、`PUT /api/option/`（见 [后台路由](../../../router/api-router.go)）。保存仍使用现有的 `{key, value}` 请求，`value` 必须传 JSON **字符串**，不是嵌套对象：

  ```json
  {"key":"GroupNotes","value":"{\"SUP-STDG-PVACP003\":\"备用线路\"}"}
  ```

- 后端拒绝无效 JSON、顶层非对象（含 `null`）、空名称或首尾带空白的名称、非字符串备注（含 `null`）以及超限值。长度限制不等于 HTTP 请求体上限；实施时核对部署入口的请求大小限制。后端不拿当前运行中的分组配置做跨键硬校验：现有设置是逐项保存、逐步同步的，避免把不同实例的瞬时状态当作备注格式错误。前端按提交时的分组列表校验关联，备注键不会反过来创建分组。
- 后端在 [配置模型](../../../model/option.go) 初始化默认值，用现有数据库加载和选项同步机制恢复已保存值。`GroupNotes` 的写入复用可检查数据库错误的持久化路径（优先现有 `UpdateOptionsBulk` 的单键用法）；不能直接继承通用 `UpdateOption` 忽略 `FirstOrCreate` / `Save` 错误的行为。非法输入或写库失败时，不更新内存、不返回成功。日志和审计只保留配置键等必要信息，不记录备注正文。

## 页面交互和保存规则

| 场景 | 预期行为 |
| --- | --- |
| 浏览和编辑 | 在「定价分组」表内加「内部备注」列，选填且有可访问名称。复用现有输入和表格组件；不改变倍率、充值倍率和详情操作。点击「保存分组设置」后持久化，刷新仍能回显。 |
| 搜索 | 现有搜索框同时匹配分组名和备注，匹配任一项即显示。搜索只影响可见行，不得丢掉隐藏行的草稿；当前输入框不能因正在编辑的文本从匹配变成不匹配而立即消失，离开该行后再应用过滤。 |
| 新增、清空、改名、删除 | 新分组备注默认空；清空则移除对应备注键。可视化模式以行的稳定 ID 关联草稿，分组改名时带走本行备注，删除则在保存时移除备注。空名称和重名按现有分组校验提示处理，不能因暂时同名而覆盖另一行备注。此处不扩展现有改名语义，不迁移用户或渠道上的分组引用。 |
| JSON 模式 | 增加独立的 `GroupNotes` 编辑区。切换模式保留同一份有效草稿；JSON 非法时提示并留在 JSON 模式，不退化成空对象。JSON 改名无法推断新旧关系，须手动移动备注键；删除须手动清除对应键。备注或分组名称集合变化时，保存前校验备注键属于最终列表（`GroupRatio` 与 `TopupGroupRatio` 的键并集）；旧孤立备注不生成行，提示到 JSON 模式处理，不静默清除。 |

保存沿用分组页的批次入口，仍是逐项请求，不宣称跨配置原子性。只改备注时只发送 `GroupNotes`，不因格式化、键顺序或行重建而重写任何倍率、可见性或自动分组配置。若同时编辑分组和备注，则先保存已有分组设置，最后提交 `GroupNotes`。每个成功项单独推进已保存基线，提交期间保持表单快照并防止重复提交；设置缓存刷新不得覆盖当前未保存草稿。如果前序失败，停止后续提交；如果分组已保存但备注写入失败，界面明确提示部分成功，保留备注草稿，下次只重试未成功项。

`GroupNotes` 仍是全量读写；本期沿用最后一次成功写入生效的语义，不保证多人同时编辑互不覆盖。实现时在可视化输入期间保留备注草稿，只在切到 JSON 或保存时序列化，不让单次备注按键触发倍率重建或整份 JSON 重写。万级分组下当前列表仍是全量加载；实施时用代表性数据记录载荷、首屏、搜索和输入表现，必要时另行推进分页或虚拟滚动。若出现高频并发修改、全量传输成为瓶颈或需要服务端搜索，再评估独立分组存储和按条更新。

## 验收条件

1. 没有 `GroupNotes` 记录时旧库和现有分组正常展示；新增非空备注后只新增一条选项记录，刷新或重启后仍能回显，清空后值为 `{}`。
2. 支持搜索名称和备注、清空、可视化模式改名或删除、与 JSON 模式切换；切换或过滤不丢草稿，无效或超限内容不会保存。
3. 仅备注变更的请求和数据库更新都只涉及 `GroupNotes`；组合保存部分失败时不误报全量成功，重试只提交未成功项，不覆盖草稿。
4. Root 可读写；无设置权限的账号不能读写该配置，普通用户分组响应不含内部备注。数据库写入失败时不把未落盘值发布到内存；备注明文不进审计日志。
5. 完成前后端回归和 SQLite、MySQL、PostgreSQL 持久化验证，并记录实际版本、命令与结果。没有数据库结构改动，不新增迁移测试脚本。

## 实施计划

1. **后端**：补默认值、共享格式及长度校验、可报告写入错误的持久化路径。沿用现有 Root 路由、审计和同步机制；优先扩展一个现有选项接口或模型测试文件，覆盖默认值、非法输入、持久化失败及重载回读。权限和用户侧不暴露作为接口验证项。
2. **前端**：接入 [账单设置默认值](../../../web/src/features/system-settings/billing/index.tsx)、同页 section registry 和设置类型，在 [保存入口](../../../web/src/features/system-settings/models/ratio-settings-card.tsx)、[分组表单](../../../web/src/features/system-settings/models/group-ratio-form.tsx) 与 [可视化编辑器](../../../web/src/features/system-settings/models/group-ratio-visual-editor.tsx) 接入备注草稿、搜索、JSON 模式与分项保存。检查共享组件复用，按 `i18n-translate` skill 补齐七种语言；将行为回归加到现有 `group-settings.test.tsx` 等适合的测试文件。
3. **联调与验证**：后端执行 `go build ./...` 和受影响包测试；前端执行 `bun run typecheck`、lint、相关 Vitest 测试及构建。用真实 SQLite、MySQL ≥ 5.7.8 和 PostgreSQL ≥ 9.6 验证首次写入、更新同一键、清空、重启/同步回读；本地 E2E 使用约定数据库，验证录入、搜索、刷新和失败后重试，并记录代表性万级数据下的页面表现，不把估算当成压测结论。

## 验证结果

前后端实现已落地，未修改数据库表结构。

- 后端：`go build ./...`、`go test ./model ./controller` 通过。`go test ./router` 的 `TestAccessTokenRouteRulesCoverEveryDashboardRoute` 失败（用量导出、模型选项和组织路由规则不匹配）；在未修改的 `dev` 上复现相同失败，本次未调整路由规则。实际启动本地 E2E 应用，确认 Root 可读 `GroupNotes`、非字符串值被拒绝、未登录读写被拒绝、用户分组响应不含备注。未在 E2E 数据库修改分组配置。Windows `-race` 检查无法构建 `runtime/cgo`。
- 数据库：`go test ./model -run '^TestGroupNotesDatabaseMatrix$' -v -count=1` 以 SQLite **3.50.4** 和本地 E2E PostgreSQL **18.3** 验证默认值不落盘、首次保存、2 MiB 上限回读、更新、清空与重载；均通过。SQLite 另验证非法输入和数据库写入失败时旧值不变。MySQL 子测试因未提供隔离实例 `TEST_MYSQL_DSN` 而跳过，不使用现有 MySQL 容器代替。部署示例的 nginx 请求体上限为 100 MiB；实际部署覆盖未核对。
- 前端：在 `web/` 执行 `bun run typecheck`、`bun run lint`（仅有其他文件的警告）、`bun run build`、`bun run test src/features/system-settings/models/__tests__`，均通过（10 个文件、89 项测试）。相关用例覆盖编辑、搜索和焦点保持、改名和删除、JSON 格式及长度校验、仅备注提交、部分失败和重试。七种语言的 i18n 同步检查通过；全站前端测试未完成。
